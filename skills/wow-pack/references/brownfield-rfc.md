# Brownfield RFC prompt (fill `wow/pb/rfc.md` so Product Brain scores 100%)

Evidence: `reference/product-brain/README.md` (Product Brain backend read at commit 9b19a89). In short:
- The scoring rules are the same as the PRD's.
- The template has FIXED `### API Gateway` and `### SLA` sections, and the RFC Agent's checklist asks for a
  circuit breaker. Those three are the source of the inventions seen so far.
- The RFC Agent will not draft without stack, authentication, high-level architecture, deployment, expected
  volume and rollout.
- It prefers indexed code over the PRD: "Código indexado > RFC/PRD previo > inferencia".

---

## Prompt (Claude Opus or Codex, acting as Engineering Manager / Tech Lead, with the repositories available)

You are completing the RFC of a change to an EXISTING system. The file `wow/pb/rfc.md` was generated by
`wow pack rfc` from Product Brain's real template: title, status, goals, non-goals, milestones and open
questions may already be filled; everything else is a `{{placeholder}}`. Product Brain will verify contracts
against the indexed code and later derive Jira epics, stories and tasks from this document.

INPUTS (the only sources of truth):
- The approved PRD: `wow/pb/prd.md`, after its Product Brain chat closed and `wow pbchat audit prd` passed.
- `wow/context-pack/*.md`, `wow/plan/PLAN.md` and `wow/plan/manifest.json`.
- `.spec-kit/discovery/architecture.md` and the repositories. Read the code to verify endpoints, DTOs, tables,
  configuration and deployment; when they disagree with a document, the code wins.

RULES:
1. Output Spanish (professional).
2. Edit `wow/pb/rfc.md` in place: replace every `{{placeholder}}`. Never rename, reorder or remove headings
   (including their 1–6 numbering), tables or columns, and keep the first line.
3. Every section states the current design first and the change second ("Hoy: … / Cambio: …").
   "Coexistencia y Fallback" is mandatory content: how old and new run together, what happens on failure, and
   how data stays consistent during the transition.
4. Every component, repository, endpoint, field, table, index, alarm or limit cites its source in backticks
   (`bff/src/routes/cases.ts:42`).
   - API fields you cannot verify: `[TBD - verificar en código/Swagger]`.
   - Anything else you cannot verify: `[SIN DEFINIR] — <qué falta y quién lo decide>`, plus an open-question row.
5. API Gateway: if there is none, write `No aplica: no hay API Gateway; la entrada es <componente real> (fuente)` in
   each of its three cells.
6. SLA: only an SLA or SLO written in a document or config; otherwise
   `[SIN DEFINIR] — no hay SLA acordado; lo decide <rol>`.
7. Resilience: list only the mechanisms present in code or config (retries with their numbers, timeouts, DLQs,
   alarms). If a circuit breaker or rate limit does not exist, say so explicitly.
8. API contracts: for each endpoint give method, path, where params go (path, query or body), and request and
   response exactly as the handler or DTO defines them; include error responses only if the code has them.
   - Fewer than three APIs: each unused block (B, C) gets `No aplica: el cambio expone <n> API(s)` in its name
     and fields.
   - More than three: add `#### D.` blocks with the same shape.
9. Data model: existing entities, keys and indexes first (cited), then the change, with types, constraints,
   indexes and any migration or backfill. `{{data_model_sql}}` holds the DDL or key schema, or
   `No aplica: <motor> sin esquema SQL; ver claves arriba`.
10. Rollout and rollback:
    - Rollout: the real feature flags and phases, or the ones this change adds.
    - Rollback: concrete and, when possible, without a new deploy (flag off, traffic switch, data restore).
    - If neither is defined: `[SIN DEFINIR] — <qué falta>` plus an open question. Never invent percentages or dates.
11. Alternativas Consideradas: a table `| Alternativa | Pros | Contras | Decisión y motivo |` with the real
    discarded options from `decisions.md` or the ADRs (cited).
12. Together, the sections must answer stack, authentication, high-level architecture, deployment, expected volume
    and rollout: the EM Agent checks those six before drafting.
13. Run `wow pack check rfc` and fix the packet until it exits 0. Then go through the CHECKLIST; do not print it.

CHECKLIST (the RFC Agent's Phase 3 plus the brownfield gates):
- [ ] `wow pack check rfc` exits 0.
- [ ] Problem and business impact are quantified with tagged, sourced numbers; the glossary covers every
      non-obvious term.
- [ ] Goals are measurable and dated (or `[SIN DEFINIR]` with an open question); non-goals are explicit.
- [ ] The Mermaid diagram contains every key component, and only real ones; changed parts are marked.
- [ ] Each API has method, path, param location, and request and response as in code (cited) or `[TBD - …]`.
- [ ] The data model has types, constraints and indexes for existing and changed entities.
- [ ] Coexistence and fallback explain old and new running together and the behaviour on failure.
- [ ] Rollout and rollback are real or `[SIN DEFINIR]`; resilience lists only existing mechanisms.
- [ ] Every risk has a mitigation; alternatives have pros, cons and the reason they were discarded.
- [ ] A developer could start the first epic without asking; if not, the missing detail is an open question.
- [ ] No API Gateway, Okta/OAuth, SLA, circuit breaker, Kong, owner name or date that is not in the inputs.

## How to paste it in Product Brain

1. Attach or index the repositories in Product Brain (ZIP or integration), so the EM Agent verifies contracts against
   the code.
2. Open the RFC step (the PRD is injected automatically). First message: `wow/pb/preamble.md`. Second message:
   "Comparto el RFC ya redactado sobre el sistema existente, verificado contra el código; mapealo campo por campo sin
   resumir", followed by the packet.
3. The EM Agent asks 3–4 rounds of questions first: answer them by pointing to the section, then confirm its summary
   with "dale".
4. Trust only `**Completitud del documento:** N%`. In Phase 3, answer each ⚠️ with evidence or move it to Preguntas
   Abiertas; never accept a ✅ without a citation.
5. Copy the chat to `wow/pb/chats/rfc.md` and run `wow pbchat audit rfc --deep`.
