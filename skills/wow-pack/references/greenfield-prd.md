# Greenfield PRD prompt (fill `wow/pb/prd.md` so Product Brain scores 100%)

> **Legado (deprecado):** solo aplica a `wow pack prd|rfc --full`. El camino por defecto es el paquete de registro,
> que sale completo de `wow pack prd|rfc` y no necesita este prompt.

Evidence and scoring rules: `reference/product-brain/README.md`.
- Any non-empty text fills a field.
- Each table counts as one unit, filled by one complete row.
- Every open-question row needs question, owner and status.

---

## Prompt (Claude Opus, after the Brief is approved)

You are completing the PRD of a NEW product or system. The file `wow/pb/prd.md` was generated by `wow pack prd`
from Product Brain's real template; fill its `{{placeholders}}`. There is no existing code to measure, so the honest
state of many numbers is "not measured yet": say so explicitly instead of inventing targets.

INPUTS (the only sources of truth):
- `wow/plan/PLAN.md` (Brief: goal, decisions, constraints, non-goals, open questions) and `wow/plan/manifest.json`.
- `wow/context-pack/*.md`: claims sourced from discovery notes kept in the repository (interviews, benchmarks, data
  exports), each with `fuente: path`.
- `pending-owner.md` for decisions that are still open.

RULES:
1. Output Spanish (professional, neutral Rioplatense).
2. Edit `wow/pb/prd.md` in place: replace every `{{placeholder}}`. Never rename, reorder or remove headings,
   tables or columns, and keep the first line.
3. Greenfield framing:
   - "Contexto" is the current market or process the product changes, not code.
   - Users are TARGET roles, with the job they need done and how they solve it today.
   - "Problema" quantifies today's pain with the evidence available; mark it [ESTIMACIÓN] when it comes from a
     sample or interviews.
4. Baselines that do not exist yet: `[SIN DEFINIR] — se mide desde el lanzamiento (<cómo>)`. Targets and deadlines:
   the owner's decision or `[SIN DEFINIR] — decide el owner`. Never invent a North Star target.
5. Missing information: `[SIN DEFINIR] — <qué falta y quién lo decide>` plus a row in "Preguntas Abiertas"
   (Owner = deciding role, Estado = `Abierta`).
6. Slots that do not apply (buyer/seller rows when the domain has no marketplace): `No aplica: <motivo>`.
7. Tables: one row per real item; delete unused template rows; every kept row is complete.
8. Keep the acceptance ids (`AC1`, `E1.C1`) verbatim.
9. Run `wow pack check prd` and fix the packet until it exits 0. Then go through the CHECKLIST; do not print it.

CHECKLIST (Product Brain's Phase 3 plus the greenfield gates):
- [ ] `wow pack check prd` exits 0.
- [ ] The problem is quantified with sourced evidence and tagged [ESTIMACIÓN] where it is an estimate.
- [ ] Target users have jobs-to-be-done and today's workaround.
- [ ] The North Star is defined; its baseline and target are real or `[SIN DEFINIR]`, never invented.
- [ ] In-Scope is the smallest MVP that validates the hypothesis; Out-of-Scope rows have a reason and a "cuando".
- [ ] Riskiest assumptions are listed with impact × uncertainty; dependencies have a role and a state.
- [ ] Main flows mention the happy path plus at least two edge cases.
- [ ] Every `[SIN DEFINIR]` has its open-question row.
- [ ] No marketplace, SLA, provider, owner name or date that is not in the inputs.

## How to paste it in Product Brain

Paste `wow/pb/preamble.md`, then the packet, with the message "Comparto el PRD ya redactado; mapealo campo por campo
sin resumir". If the agent insists on Discovery, confirm its summary with "dale". Copy the chat to
`wow/pb/chats/prd.md` and run `wow pbchat audit prd --deep`.
