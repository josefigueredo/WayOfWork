# Greenfield RFC prompt (fill `wow/pb/rfc.md` so Product Brain scores 100%)

> **Legado (deprecado):** solo aplica a `wow pack prd|rfc --full`. El camino por defecto es el paquete de registro,
> que sale completo de `wow pack prd|rfc` y no necesita este prompt.

Evidence and scoring rules: `reference/product-brain/README.md`.
- The template has fixed `API Gateway` and `SLA` sections.
- The EM Agent needs stack, authentication, architecture, deployment, volume and rollout before it drafts.

---

## Prompt (Claude Opus or Codex, acting as Engineering Manager / Tech Lead)

You are completing the RFC of a NEW system. The file `wow/pb/rfc.md` was generated by `wow pack rfc`.
"Coexistencia y Fallback" is already `No aplica: sistema nuevo`. Fill every remaining `{{placeholder}}` with a
proposed design and its trade-offs. Nothing exists in code yet, so mark proposals as proposals and never present
them as verified.

INPUTS (the only sources of truth):
- The approved PRD (`wow/pb/prd.md`, audited), `wow/plan/PLAN.md` (decisions D1…), `wow/plan/manifest.json`.
- `wow/context-pack/decisions.md` and `contracts.md` (organisation standards, platform constraints, chosen
  providers), each sourced.

RULES:
1. Output Spanish (professional).
2. Edit `wow/pb/rfc.md` in place: replace every `{{placeholder}}`; keep headings, numbering, tables and the first line.
3. Every component, repository and API is NEW. Mark each one "(propuesta)" and explain its responsibility.
   Repositories are the ones to be created, with the owning team as a role.
4. Stack and providers: only those decided in `decisions.md` or the Brief. If a choice is open, present the
   alternatives in section 5 and record the decision as an open question; do not pick one silently.
5. API Gateway and SLA: describe them only if a decision exists; otherwise `[SIN DEFINIR] — <qué decidir y quién>`.
   If the design has no gateway, write `No aplica: <por qué>`.
6. API contracts: method, path, param location, request and response as PROPOSED, marked
   "(contrato propuesto)". Fewer than three APIs: `No aplica: el diseño expone <n> API(s)` in the unused blocks.
7. Data model: proposed entities, keys, indexes and types. Rollout: phases and flags for the first release.
   Rollback: how to disable the release without a deploy, or `[SIN DEFINIR]` with an open question.
8. Alternativas Consideradas: `| Alternativa | Pros | Contras | Decisión y motivo |`, with at least the options
   behind each decision D1….
9. Run `wow pack check rfc` and fix the packet until it exits 0. Then go through the CHECKLIST; do not print it.

CHECKLIST (the RFC Agent's Phase 3 plus the greenfield gates):
- [ ] `wow pack check rfc` exits 0.
- [ ] Problem, glossary and quantified business impact (tagged estimates where applicable).
- [ ] Goals are measurable and dated or `[SIN DEFINIR]`; non-goals are explicit.
- [ ] The diagram shows every proposed component; proposals are marked as such.
- [ ] Proposed contracts have method, path, params, request and response.
- [ ] The data model has types, constraints and indexes; rollout has phases or flags; rollback is concrete or
      `[SIN DEFINIR]`.
- [ ] Alternatives with pros, cons and reasons for every key decision; risks with mitigation.
- [ ] No provider, SLA, gateway, owner name or date that is not decided in the inputs.

## How to paste it in Product Brain

Paste `wow/pb/preamble.md`, then the packet, with the message "Comparto el RFC ya redactado; mapealo campo por campo
sin resumir". Answer the EM Agent's question rounds by pointing to the sections and confirm with "dale". Copy the
chat to `wow/pb/chats/rfc.md` and run `wow pbchat audit rfc --deep`.
