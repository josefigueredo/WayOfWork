# Epic packet prompt (fill `wow/pb/epic-E<n>.md` so Product Brain scores 100% and Jira export works)

Evidence: `reference/product-brain/README.md`.
- A Product Brain epic is a JSON document of 26 fields; `user_stories` holds stories of 20 fields each.
- Every property counts toward completion, so one empty list inside one story leaves `user_stories` partial.
- Stories need Gherkin acceptance criteria, a canonical component (FE, BE, BO, QA, DEVOPS, INFRA, BFF or AI),
  Fibonacci story points, the 4 fixed DoR items, the 11 fixed DoD items with si/no, and tasks with purpose and
  how-to.

---

## Prompt (Claude Opus or Codex, with the approved RFC and the repositories available)

You are completing one Product Brain epic. The file `wow/pb/epic-E<n>.md` was generated by
`wow pack epic --id E<n>` from the upstream manifest: one epic, one story per manifest task (US-001…), one Product
Brain task per subtask. Fill every `{{placeholder}}`.

INPUTS (the only sources of truth): the audited RFC (`wow/pb/rfc.md`) for endpoints, tables and components; the PRD;
`wow/plan/manifest.json`; `wow/context-pack/*.md`.

RULES:
1. Output Spanish (professional). Edit the file in place; keep every heading, table, label and the first line.
   The `(field)` suffix in each label is how the fields are mapped: never remove it.
2. Enums and formats must be valid, because Product Brain exports them to Jira:
   - criticality and priority: Alta, Media or Baja;
   - status: todo;
   - dates: YYYY-MM-DD;
   - quarter: Q<1-4>/YYYY;
   - big_move: Sí or No;
   - component: FE, BE, BO, QA, DEVOPS, INFRA, BFF or AI;
   - story points: 1, 2, 3, 5, 8 or 13.
   If the value is unknown, LEAVE the `{{placeholder}}` and report it to the owner: `[SIN DEFINIR]` would break the
   export.
3. Free-text fields with no information: `[SIN DEFINIR] — <qué falta y quién lo decide>`. Lists with no items:
   a single item `Ninguno` or `Ninguna`, never an empty list.
4. Stories:
   - `user_story_text` reads "Como <persona> quiero <necesidad> para <objetivo>";
   - scope and out_of_scope are single strings;
   - business rules and edge cases are lists (at least two edge cases: invalid input and failure of a dependency);
   - technical_info cites the RFC section and the code paths.
5. Acceptance criteria stay as `AC<n> — Dado … Cuando … Entonces …`, keeping the `AC<n>` id.
6. Do not edit the Definition of Ready or Definition of Done items. Every DoD answer starts as `no`.
7. Tasks: replace `{{purpose}}` and `{{how_to}}` with concrete steps taken from the RFC (exact endpoint, table, DTO
   or pipeline). Never write generic tasks such as "Implementar backend". A story with `- {{tasks}}` needs at least
   one task line in the same format: `<[AREA] título> — Propósito: … — Cómo: … — Componente: … — Estado: todo`.
8. A story above 8 points is a finding: report it to split the manifest task. Do not split it here.
9. Run `wow pack check epic --id E<n>` and fix the packet until it exits 0 (100% and no errors).

## How to paste it in Product Brain

Open the EPIC step (one epic per document; the PRD and RFC are injected). First message: `wow/pb/preamble.md`.
Second message: "Comparto la épica ya desglosada; mapeala campo por campo sin resumir ni agregar historias", followed
by the packet. Copy the chat to `wow/pb/chats/epic-E<n>.md` and run `wow pbchat audit epic-E<n> --deep`. Export to
Jira from Product Brain, then record the key with `wow plan freeze --epics E<n>=<KEY>`.
